# klipper-doctor: decisions

Why the project is the way it is, newest first. One entry per decision: the date it was made, what was decided, and why. Entries are records: when a decision stops being true, leave it and add `Superseded YYYY-MM-DD: <what replaced it>.` to its end, then add the new decision above.

- 2026-11-22: The docs live in the repo (AGENTS.md, docs/), and the maintainer's project notes point at them. Why: an agent working in a clone sees the repo, not those notes.
- 2026-11-14: Releases publish to npm through trusted publishing over OIDC, with provenance and no stored token, when `NPM_TOKEN` is not set. Why: nothing stored in the repo's secrets. The trusted publisher entry on npmjs.com must allow `npm publish`, or the run waits for a 2FA approval. Version 0.5.1 was never published: a stale local TypeScript built the wrong `dist/`, and the CI `dist/` check stopped it.
- 2026-11-02: Landings use the normal remote flow: push to the remote and publish releases through `publish.yml`. Why: it replaces the earlier rule that work stayed on the local machine. Posting about the project stays with the maintainer.
- 2026-11-02: When a log holds several sessions, the last is still the one analysed, and a clean last session stays exit 0. An earlier failure is named inside `no-failure-found`. Why: most people restart Klipper before they grab the log. Still true: `findEarlierFailure` feeds `noFailure`.
- 2026-11-02: Rules look only at what came before the first shutdown plus the reason Klipper gave. Why: every MCU reports `Command request` after any host shutdown, so that string alone proves nothing, and a later cascade or a quoted dump must not add a diagnosis. Still true: `causalLines` in `src/core/cause.ts`.
- 2026-11-02: Complement the existing log graphers, credit them, and make no "first" or "only" claim. Why: Reddit and Discord prior art was not checked, so the copy cannot claim either. Still true: the README has an "Other tools" section crediting them.
- 2026-11-02: Fewer correct rules over many shaky ones. Every rule traces to Klipper docs or source, and no thresholds are invented. Still true: CONTRIBUTING.md says "No source, no rule".
- 2026-11-02: Published under the maintainer's personal GitHub, kd-011/klipper-doctor, not an organisation. Why: it replaces the earlier plan for an organisation and a trace-free identity. Still true for the repo and npm owner in `package.json`. The recorded copyright line "Hotend" does not hold: `LICENSE` has read "Copyright (c) 2026 kd-011" since the first commit, and only the README says "Built by Hotend".
- 2026-11-02: The web version analyses in the browser. Nothing is uploaded or stored, and v1 has no share-by-link. "Copy as markdown" covers sharing. Why: a log can hold hostnames and serial numbers, which CONTRIBUTING.md asks people to remove before they paste one. That page is in another repo and was not checked here; the README says the file stays in the browser, and `--md` is the markdown output.
- 2026-11-02: A TypeScript engine with zero runtime dependencies, running unchanged in Node and the browser. Only the CLI touches the filesystem. Why: one codebase for both. Still true: `tsconfig.core.json` gives `src/core` no Node types.
- 2026-11-02: One tool, two reports, one input. Not two products. Why: Klipper writes the parsed config into `klippy.log` at every start, so one log gives both. Still true: `analyze` returns `crash` and `config` findings from one text.
